Security

yokoten no longer prints a user name from a home folder path that is not your own $HOME (#1237). The output, the stop log, `redact`, upstream notes and the board now show the name as `<user>`. This covers a WSL user's Windows home (`C:\Users\<name>`, `/mnt/c/Users/<name>`, `/cygdrive/c/Users/<name>`), device and share forms (`\\?\C:\Users\<name>`, `\\server\c$\Users\<name>`, `\\wsl$\<distro>\home\<name>`), JSON-escaped paths, and another account's home. A Windows name with spaces or punctuation (`Jane Doe`, `O'Brien`) is hidden whole. A shared account (`runner`, `Public`, `Shared`) and a web route under `/home` (`/home/settings`) stay. A post, a desk message, a note or a lesson pack is refused (rule `user-folder`) when it holds a name in a drive form, a WSL share, or `/Users/<name>`. A name under `/home` is refused too when it is your own user, in $HOME or USERPROFILE, when it has capitals or other characters, or when the path goes on into a dot-folder (`/home/<name>/.ssh`). Any other lower-case `/home/<word>` is only a note, since it may be a route. The worker guard now reads a `cd` path through one path reader: a Windows short name such as `RUNNER~1` in a worker's own worktree path is accepted, and a path part that Windows reads two ways (`...`, `a.`) is refused.
