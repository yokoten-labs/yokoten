Security

yokoten no longer prints a user name from a home folder path that is not your own $HOME (#1237). The output, the stop log, `redact`, upstream notes and the board now show the name as `<user>`. This covers a WSL user's Windows home (`C:\Users\<name>`, `/mnt/c/Users/<name>`, `/cygdrive/c/Users/<name>`), device and share forms (`\\?\C:\Users\<name>`, `\\server\c$\Users\<name>`, `\\wsl$\<distro>\home\<name>`), JSON-escaped paths, and another account's home. A Windows name with spaces or punctuation (`Jane Doe`, `O'Brien`) is hidden whole. A shared account (`runner`, `Public`, `Shared`) and a web route (`/home/settings`, `/users/123`) stay. A post, a desk message, a note or a lesson pack that still holds such a name is refused (rule `user-folder`); a lower-case `/home/<word>` with no drive is a note there, since it may be a route. The worker guard now reads a `cd` path through one path reader: a Windows short name such as `RUNNER~1` in a worker's own worktree path is accepted, and a path part that Windows reads two ways (`...`, `a.`) is refused.
